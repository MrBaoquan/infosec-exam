# 题型 03 · 子网划分方案设计（需求反推掩码）

> **本次原题**：某单位分配了一个 B 类地址，计划将内部网络分成 35 个子网，每个子网的主机数目将近 800 台，可行的掩码方案是？
> **答案**：**255.255.252.0（/22）**

:::caution 先说题干里的一处矛盾
原题同时出现「分成 35 个子网」和「将来要增加到 16 个子网」—— 35 增加到 16 是**变小**，逻辑不通。两种可能：
1. **「35」是「3~5」漏了波浪号** → 现在 3~5 个，将来 16 个；
2. 「将来要增加到 16 个子网」是**多抄的残句**，实际需求就是 35 个子网 + 800 台主机。

两种读法我都在第四节算了一遍，并说明各自答案。**考场上按题干给的数字算、把步骤写全**，比猜原意更重要。
:::

## 一、识别信号（这是「反向题」，与题型01 方向相反）

- 给**需求量**，问**掩码应该填什么**：几个子网、每个子网几台主机、几个部门、几栋楼。
- 出现「分成 N 个子网」「将来要增加到 M 个」「每子网不少于 K 台主机」。
- 问「可行的/最合适的掩码方案是」，选项是若干个 `255.255.x.0`。
- 问「需要借几位主机位」「能划分出多少个子网」。

> 对比记忆：**题型01 是"给 IP + 掩码 → 算地址"；题型03 是"给需求 → 反推掩码"**，最终都要回到同一套「块大小」算法做验证。

## 二、核心原理（双向约束，取交集）

一个子网划分方案要同时满足两个方向的要求，而它们**争的是同一块主机位**：

```text
地址块总位数（B 类 = 32 − 16 = 16 位）
        ├── 借给子网号的 k 位  →  决定能分多少子网：2^k
        └── 留给主机的 n 位    →  决定每个子网多少台：2^n − 2
                  k + n ≤ 地址块主机位     ← 冲突在这里
```

三条铁律：

1. **子网数只要"够"，不要"刚好"**：2 的幂天生台阶化，35 个需求只能给 64（6 位），不能给 32（5 位，不够）。
2. **主机数必须减 2**：网络地址 + 广播地址不可分配。
3. **k + n 不能超过地址块的主机位**：B 类 16 位、C 类 8 位、A 类 24 位。超了就是**方案不可行**，这是最容易忽略的考点。

## 三、通用解题步骤（照着套，五步）

1. **定默认前缀**：A 类 /8、B 类 /16、C 类 /24。（本题 B 类 → /16，主机位共 16 位）
2. **由子网数求 k**：找最小的 k 使 $2^{k} \ge$ 子网需求数（**向上取整**）。
3. **由主机数求 n**：找最小的 n 使 $2^{n} - 2 \ge$ 每子网主机需求数。
4. **校验可行性**：$k + n \le$ 地址块主机位？
   - 成立 → 前缀 = 默认前缀 + k，换算掩码；
   - 不成立 → 方案不可行，需换更大地址块，或用 VLSM 按需拆分。
5. **反算验证（必写）**：子网数 $2^{k}$、每子网可用 $2^{n}-2$，都要 ≥ 需求；再用「块大小 = 256 − 关键字节」抽查子网边界。

## 四、本题完整解答

### 读法一（推荐）：35 个子网，每子网 800 台

**步骤 2 · 由子网数求 k**

```text
2^5 = 32 < 35   ✗ 不够
2^6 = 64 ≥ 35   ✓  → k = 6
```

**步骤 3 · 由主机数求 n**

```text
2^9  − 2 = 510  < 800  ✗ 不够
2^10 − 2 = 1022 ≥ 800  ✓ → n = 10
```

**步骤 4 · 校验可行性**

```text
k + n = 6 + 10 = 16 = B 类主机位总数  ✓ 恰好用完，没有浪费也没有冲突
```

**步骤 5 · 换算掩码**

```text
前缀 = B 类默认 16 + 借位 6 = 22  →  /22
/22 = 11111111.11111111.11111100.00000000
    = 255.255.252.0
```

> ✅ **可行掩码方案：255.255.252.0（/22）**

**反算验证（这是答题的得分点，别省）**

| 校验项 | 需求 | /22 方案实际 | 结论 |
|--------|:----:|:------------:|:----:|
| 子网个数 | ≥ 35 | $2^{6}$ = **64** 个 | ✔ 够，余 29 个 |
| 每子网可用主机 | ≥ 800 | $2^{10}-2$ = **1022** 台 | ✔ 够，余 222 台 |
| 位数占用 | ≤ 16 | 6 + 10 = **16** | ✔ 恰好填满 |
| 掩码 | — | **255.255.252.0** | — |

**子网长什么样（第 3 字节按 4 递增）**

```text
块大小 = 256 − 252 = 4（作用在第 3 字节）
子网序列：0, 4, 8, 12, ……, 252   共 64 个

第 1 个子网： x.y.0.0/22   范围 x.y.0.0  – x.y.3.255
第 2 个子网： x.y.4.0/22   范围 x.y.4.0  – x.y.7.255
第 3 个子网： x.y.8.0/22   范围 x.y.8.0  – x.y.11.255
```

**关于「将来要增加」**：/22 一次给出 **64 个子网**的容量，只要将来规模不超过 64 个，这个方案**一直成立**，不必改掩码。若将来要超过 64 个（比如 100 个），则 k = 7，$7 + 10 = 17 > 16$ → **B 类装不下**，必须改用 VLSM 或申请更大地址块。

### 读法二：若题干是「现在 3~5 个，将来增到 16 个」

- 由子网数：$2^{4} = 16 \ge 16$ → k = 4（若还要容纳 3~5 个，4 位更宽裕）
- 由主机数：仍是 n = 10（1022 ≥ 800）
- 校验：$4 + 10 = 14 \le 16$ ✔ 富余 2 位
- 前缀 = 16 + 4 = **20** → **255.255.240.0（/20）**
- 实际效果：16 个子网，每子网 $2^{12}$ = 4096 个地址（可用 4094 台），块大小 16

**两种读法的差别只在"子网数需求"这一个数字上，方法完全一样。** 做题时按题干明确给出的那个数算，并把 k、n、校验三步写全即可。

## 五、变式训练（先自己做，再展开答案）

<details>
<summary><b>变式 1</b>：B 类地址，要 60 个子网，每子网 700 台主机，掩码填什么？</summary>

- 子网数：$2^{6} = 64 \ge 60$ → k = 6（$2^{5}=32$ 不够）
- 主机数：$2^{10}-2 = 1022 \ge 700$ → n = 10（$2^{9}-2 = 510$ 不够）
- 校验：$6 + 10 = 16 \le 16$ ✔

**答案：/22 = 255.255.252.0**（64 个子网 × 1022 台）

</details>

<details>
<summary><b>变式 2</b>：B 类地址，要 20 个子网，每子网 2000 台主机，掩码填什么？</summary>

- 子网数：$2^{5} = 32 \ge 20$ → k = 5
- 主机数：$2^{11}-2 = 2046 \ge 2000$ → n = 11（$2^{10}-2 = 1022$ 不够）
- 校验：$5 + 11 = 16 \le 16$ ✔

**答案：/21 = 255.255.248.0**（32 个子网 × 2046 台）

</details>

<details>
<summary><b>变式 3</b>：C 类地址 192.168.1.0，要 6 个子网，每子网 30 台主机，掩码填什么？</summary>

- 默认前缀 /24，主机位共 **8** 位
- 子网数：$2^{3} = 8 \ge 6$ → k = 3
- 主机数：$2^{5}-2 = 30 \ge 30$ → n = 5
- 校验：$3 + 5 = 8 \le 8$ ✔ 恰好

**答案：/27 = 255.255.255.224**（8 个子网 × 30 台，块大小 32）

</details>

<details>
<summary><b>变式 4</b>（可行性判断）：C 类地址，要 10 个子网，每子网 30 台主机，能做到吗？</summary>

**做不到。**

- 子网数：$2^{4} = 16 \ge 10$ → k = 4
- 主机数：$2^{5}-2 = 30 \ge 30$ → n = 5
- 校验：$4 + 5 = 9 > 8$（C 类只有 8 位）✗ **超了 1 位**

若强行取 /28（k=4, n=4）：每子网只剩 $2^{4}-2 = 14$ 台，**不满足 30 台**。
→ 结论：**必须换用更大的地址块**（如 B 类），或用多个 C 类地址、VLSM/超网方案。

> 这类题只要看到「k + n 超了」，就直接答"不可行"并写出超出的位数，别硬凑掩码。

</details>

<details>
<summary><b>变式 5</b>（反向核对）：B 类地址上用 255.255.255.192，能分多少子网、每子网几台？</summary>

- /26 = 255.255.255.192 → 借位 k = 26 − 16 = **10** 位 → 子网数 $2^{10}$ = **1024** 个
- 主机位 n = 32 − 26 = **6** 位 → 每子网可用 $2^{6}-2$ = **62** 台
- 块大小（第 4 字节）= 256 − 192 = 64

</details>

<details>
<summary><b>变式 6</b>（增长校验）：本题若将来要扩到 100 个子网、仍要 800 台/子网，还能用 B 类吗？</summary>

**不能。**

- 由 100 个子网：$2^{7} = 128 \ge 100$ → k = 7
- 由 800 台主机：n = 10
- 校验：$7 + 10 = 17 > 16$ ✗ 超出 B 类主机位 1 位

→ 必须：① 改用 A 类地址块；② 申请多个 B 类；③ 用 **VLSM** 按实际需求拆分，不做等长子网。

</details>

## 六、易错点与陷阱

| 陷阱 | 错误做法 | 正确做法 |
|------|----------|----------|
| **子网数向下取整** | 35 个 → 取 5 位（32 个） | **向上**取到 6 位（64 个） |
| **主机数忘了减 2** | 800 → 取 9 位（512 个够？） | $2^{10}-2 = 1022$ 才够，n = 10 |
| **默认前缀记错** | B 类当 /24 算 | B 类默认 **/16**（主机位 16 位） |
| **不做 k+n 校验** | 算出掩码就交卷 | 必须验 $k+n \le$ 地址块主机位 |
| **按现状算、忽略"将来"** | 只看 35，不留余量 | 增长需求要按**未来**数量算 |
| **掩码换算错** | /22 写成 255.255.248.0 | /22 → 第三字节 252；/21 才是 248 |
| **只给掩码不写过程** | 直接写 255.255.252.0 | 写 k、n、校验三步（过程分） |

:::caution 掩码换算别串行
`/20 = 240`、`/21 = 248`、`/22 = 252`、`/23 = 254`、`/24 = 255`。
记法：**关键字节 = 256 − 该子网的地址块大小**。块大小 16 → 240；块大小 4 → 252。
:::

## 七、考点速记卡（复习只看这一块）

### 口诀

> **子网数向上取 k，主机数减二取 n；k 加 n 不许超位数（B 类 16、C 类 8）；前缀 = 默认前缀 + k。**

### 五步模板

```text
① 默认前缀：A /8   B /16   C /24   → 主机位 24 / 16 / 8
② 子网数 S：找最小 k，使 2^k ≥ S
③ 主机数 H：找最小 n，使 2^n − 2 ≥ H
④ 校验：k + n ≤ 主机位？ 超了 → 不可行
⑤ 前缀 = 默认 + k；掩码换算；反算验证 2^k 与 2^n−2
```
