## 二、密码学（Q01–Q10）

#### Q01 ★★★ 数字信封与数字签名
- **问**：A 向 B 发合同，要求保密、可认证、抗抵赖。A 发出的数据由哪几部分组成，各用谁的哪把密钥？
- **答**：① 原文用**随机会话密钥对称加密**（保密性）② 会话密钥用 **B 的公钥**封装 = **数字信封** ③ 原文**摘要**用 **A 的私钥**签名（完整性 + 身份认证 + 抗抵赖）④ B 侧：**B 私钥解信封 → 解密 → A 公钥解签名得摘要 → 同算法重算摘要 → 比对**

#### Q02 ★★★ 为什么必须用混合加密
- **答**：① 对称算法**速度快**，适合大数据量 ② 非对称算法解决**密钥分发**问题，但**慢**且**只能加密小于模长的数据** ③ 结论：**对称加密数据 + 非对称保护密钥**，兼得效率与安全

#### Q03 ★★★ 哈希函数的性质与用途
- **答**：性质：**单向不可逆、定长输出、抗碰撞、雪崩效应**。用途：**完整性校验、口令加盐存储、数字签名、消息认证码（MAC）、区块链**。
- **追问「签名为何先哈希」**：① 非对称算法只能处理小于模长的数据块，哈希把任意长度**压成定长** ② 签名运算远慢于哈希，**效率** ③ 摘要与原文**分离**，可只传签名值存证 ④ 抗碰撞性把「完整性」变成「摘要是否一致」

#### Q04 ★★ 数字证书与证书验证
- **答**：① 证书把**公钥与身份绑定**，由 **CA 用私钥签名**，格式 **X.509** ② PKI 组成：**CA、RA、证书库、CRL/OCSP、时间戳** ③ 验证四步：**验 CA 签名 → 查有效期 → 查吊销状态（CRL/OCSP）→ 链到受信根 CA** ④ CRL 是**定期发布的全量吊销列表**（有延迟），OCSP 是**在线实时查询**

#### Q05 ★★ 对称与非对称的对比
- **答**：密钥管理（1 把共享 vs 一对公私钥）、速度（快 vs 慢）、典型算法（**DES/AES/SM4** vs **RSA/ECC/SM2**）、用途（数据加密 vs **密钥分发与签名**）、抗抵赖（**不能** vs 能）

#### Q06 ★★ 国产密码算法
- **答**：**SM1** 对称分组（不公开，硬件实现）；**SM2** 基于**椭圆曲线**的公钥算法（签名/加密/密钥交换，256 位）；**SM3** 哈希，输出 **256** 位；**SM4** 分组密码，分组 **128** 位、密钥 **128** 位、**32** 轮；**SM9** **标识密码**（以身份标识为公钥，免证书）；**ZUC** 序列密码（4G）

#### Q07 ★★ 密钥管理生命周期
- **答**：**生成 → 分发（安全通道/信封）→ 存储（加密、硬件保护）→ 使用（最小暴露）→ 更新/轮换（定期）→ 备份与恢复 → 销毁（覆写、介质销毁）**。要点：**密钥不与数据同存**、**主密钥保护工作密钥**

#### Q08 ★★ 分组密码工作模式
- **答**：**ECB**（相同明文块得相同密文块，**暴露数据模式，禁止用于业务数据**）、**CBC**（链式，需 IV，错误传播）、**CFB/OFB**（流式）、**CTR**（计数器，可并行，可随机访问）。**IV 必须随机且不可复用**

#### Q09 ★★ DH 密钥交换与中间人
- **答**：① 双方各生成私钥，交换 **g^a mod p / g^b mod p**，各自算出共享密钥 **g^(ab) mod p** ② 基于**离散对数难题** ③ 缺陷：**不认证身份，易受中间人攻击** ④ 解决：**用证书/签名对交换值做认证**（如 TLS 用证书 + ECDHE）

#### Q10 ★ Kerberos 与单点登录
- **答**：① 基于**对称密钥**的**可信第三方（KDC = AS + TGS）** 认证 ② 流程：**AS 认证发 TGT → 凭 TGT 向 TGS 申请服务票据 → 凭服务票据访问应用** ③ 提供 **SSO** ④ 风险：**KDC 成为单点**、时间同步敏感（防重放）

## 三、网络防护（Q11–Q20）

#### Q11 ★★★ 防火墙 / IDS / IPS
- **答**：三问定位：**串联还是旁路 → 四层还是七层 → 放行/告警/阻断**。
  防火墙：**串联**边界、**三四层 + 连接状态**、放行或拒绝、**看不见内容**；
  IDS：**旁路**（镜像/分光）、**七层**、**只告警记录**、**拦不住**；
  IPS：**串联**、七层、**实时阻断**、**怕误报与单点故障**。
- **选 IPS 的前提**：**Bypass/HA、误报调优与观察期、性能与延迟评估、日志集中与值守**

#### Q12 ★★★ IPSec VPN
- **答**：① **AH（协议号 51）** 只做认证与完整性，**不加密**；**ESP（50）** 提供加密，可选认证 ② **传输模式**保护 IP 载荷（主机到主机），**隧道模式**保护整个 IP 包（网关到网关，**组网最常用**）③ 由 **IKE** 协商 SA（UDP **500**）④ 只能保护 IP 层，**对上层应用透明**

#### Q13 ★★ TLS 与 HTTPS
- **答**：① 握手协商**协议版本、密码套件、随机数**，用**服务器证书验证身份**，通过 ECDHE 交换密钥（**前向安全**）② 之后用**对称会话密钥**加密应用数据 ③ 提供**保密性、完整性、身份认证** ④ HTTPS = HTTP over TLS，端口 **443**；证书校验靠 **CA 信任链**

#### Q14 ★★ 无线安全演进
- **答**：**WEP**：RC4 + **24 位 IV**，IV 重用 → 易破解；**WPA**：**TKIP + MIC**；**WPA2**（802.11i）：**CCMP/AES**；**WPA3**：**SAE** 抗离线字典。企业级统一用 **802.1X + EAP + RADIUS**

#### Q15 ★★ DDoS 分类与防护
- **答**：分类：**流量型**（带宽耗尽）、**协议型**（SYN Flood、ACK Flood）、**应用层**（CC、慢速攻击）。防护：**流量清洗/ Scrubbing、CDN 分散、限速与连接数限制、SYN Cookie、Anycast、黑名单与指纹识别、应急预案**

#### Q16 ★★ ARP 欺骗
- **答**：原理：**ARP 无认证、无状态**，攻击者伪造 ARP 应答（把自己 MAC 绑定到网关 IP），实现**中间人/断网**。防护：**静态 ARP 绑定、ARP 防火墙/DAI、DHCP Snooping、端口安全、VLAN 隔离、加密通信兜底**

#### Q17 ★★ DNS 欺骗与缓存投毒
- **答**：原理：伪造 DNS 应答或污染递归服务器缓存，把域名解析到恶意 IP。防护：**DNSSEC**（来源认证与完整性，不提供保密）、**随机化源端口与事务 ID**、**限制递归查询、分离内外网 DNS、本地 hosts 兜底**

#### Q18 ★★ 安全区域与 DMZ 设计
- **答**：分层：**互联网 → 边界防火墙 → DMZ（对外服务器）→ 内网防火墙 → 核心业务区**；DMZ 放**必须对外提供服务**的主机（Web、邮件、DNS、反向代理），**数据库不放在 DMZ**；区域间**最小放行 + 双向策略 + 审计**；旁路接 IDS、串联 IPS

#### Q19 ★★ 网络隔离与网闸
- **答**：**物理隔离**（完全不连通）→ **网闸/单向导入**（协议剥离、内容净化、**单向传输**）→ **防火墙 + 代理**（逻辑隔离）。**正向隔离**指内网向外发（数据外发），**反向隔离**指外向内取；关键业务网常要求**单向导入、禁止双向直连**

#### Q20 ★ 蜜罐与蜜网
- **答**：作用：**诱捕攻击、转移目标、收集样本与手法、预警**。风险：**被当作跳板、法律与取证风险、运维成本**；部署要点：**隔离网段、严格访问控制、不可存放真实数据、全量日志**

## 四、系统与访问控制（Q21–Q27）

#### Q21 ★★★ 访问控制三模型
- **答**：**DAC**：**资源属主**自主授权可转授（ACL、权限位），适合小范围变动少；**MAC**：**系统**按「主体标签 vs 客体密级」强制判定（管理员只打标签配策略），**BLP 不上读不下写**，能防特洛伊木马；**RBAC**：权限打包给**角色**，用户通过角色获得，适合人员频繁变动、可做**职责分离**。
- **口诀**：DAC 属主给钥匙，MAC 系统比标签，RBAC 权力挂岗位。

#### Q22 ★★ 最小特权落地（动作化）
- **答**：**默认拒绝 → 按需授权（双签审批）→ 定期复核（季度/半年，部门负责人签字）→ 离职转岗 24 小时内回收 → 职责分离 SoD（申请与审批分离）→ 特权账号单管、单独审计、禁止共享**

#### Q23 ★★ 认证三要素与协议
- **答**：三要素：**你知道什么 / 你拥有什么 / 你是什么**；**双因素**必须来自不同类别。**PAP 明文传口令**；**CHAP 三次握手、挑战应答、不传口令本身**；**RADIUS 集中认证（1812/1813）**；**Kerberos 对称密钥 + TGT**

#### Q24 ★★ 单点登录 SSO
- **答**：原理：**统一认证中心签发凭证（票据/Token/SAML 断言）**，各应用**信任该凭证**，实现一次登录多点通行。风险：**认证中心成为单点故障与最高价值攻击目标**、**Token 泄露即全通**、**注销不同步**。防护：**强认证、短时效 Token、集中审计、单点故障冗余**

#### Q25 ★★ 操作系统加固
- **答**：**账号**（禁用默认/多余账号、强口令策略、最小权限、禁用 root 远程）→ **补丁**（及时更新）→ **服务最小化**（关端口、卸组件）→ **访问控制**（SELinux/AppArmor 强制访问控制、文件权限）→ **日志与审计**（集中转发、防篡改）→ **基线核查与定期扫描**

#### Q26 ★★ 缓冲区溢出
- **答**：原理：**未做边界检查的输入写入固定长度缓冲区**，覆盖**返回地址/函数指针**，劫持执行流执行攻击代码。防护：**栈保护（Canary）、DEP/NX、ASLR、安全字符串函数、编译器边界检查、代码审计与静态分析、最小权限运行**

#### Q27 ★ 数据库安全
- **答**：**分账号最小权限**（应用账号不给 DBA 权限）、**敏感字段加密与脱敏**、**口令加盐哈希存储**、**审计与行为基线**、**防注入（预编译）**、**备份加密与异地**、**关闭外网直连与默认端口**、**定期漏洞与配置核查**

## 五、恶意代码与应急（Q28–Q33）

#### Q28 ★★★ 病毒 / 蠕虫 / 木马
- **答**：**病毒**：**寄生**宿主文件、**需用户触发**、有传染性；**蠕虫**：**独立运行、自主传播**（利用漏洞/弱口令），可耗尽带宽；**木马**：**伪装正常程序**，以**远程控制/窃密**为目的，通常不自我复制。补充：**后门、僵尸网络、Rootkit（隐藏）、逻辑炸弹（条件触发）、间谍软件**

#### Q29 ★★★ 应急响应六阶段
- **答**：**准备 → 检测 → 抑制 → 根除 → 恢复 → 跟踪（总结）**（PDCERF）。
  关键动作：抑制阶段**先止损**（隔离、断网、封禁、改密），**不要急着重装**；根除阶段清马、打补丁、堵入口；恢复阶段**验证后再上线**；跟踪阶段**复盘 + 改进 + 报告**。

#### Q30 ★★ 电子数据取证
- **答**：原则：**及时性、完整性（哈希校验）、合法性（程序合规）、只读性（写保护）、链式保管**。
  步骤：**保护现场 → 固定证据（拍照、哈希）→ 提取 → 分析 → 出具报告**。
  易失性顺序（先取易失）：**寄存器/缓存 → 内存 → 网络连接与 ARP → 临时文件 → 磁盘 → 备份/归档 → 打印件**。

#### Q31 ★★ 勒索软件处置
- **答**：① **立即隔离**感染主机与网段，阻断横向 ② **保留样本与日志**（不格式化）③ **评估备份可用性**（离线/异地备份是唯一可靠恢复手段）④ **不轻易支付赎金**（可能拿不到密钥、助长犯罪、可能被标记为易受攻击目标）⑤ **定位入口**（钓鱼、暴露的 RDP/VPN、漏洞）并修复 ⑥ **上报监管与公安**，按预案恢复。

#### Q32 ★★ 挖矿木马与僵尸网络识别
- **答**：特征：**CPU/GPU 异常占用、异常外联矿池域名与端口、计划任务/自启动异常、SSH 爆破痕迹**；僵尸网络：**周期性心跳外联、固定 C2 域名、DGA 域名**。处置：**断网取证 → 清除持久化 → 改密 → 补丁 → 出向流量管控与威胁情报封禁**

#### Q33 ★ 漏洞管理流程
- **答**：**资产梳理 → 漏洞发现（扫描/众测/情报）→ 风险评估（可利用性 × 业务影响，CVSS 参考）→ 修复排序（先高危可利用）→ 修复与验证（复测）→ 例外管理与跟踪闭环**

## 六、应用安全（Q34–Q39）

#### Q34 ★★★ SQL 注入 / XSS / CSRF
- **答**：一句话分开：**注入看「谁在执行字符串」，跨站看「请求是谁发出的」**。
  SQL 注入：成因=**代码与数据未分离**；载荷三要素=**闭合 → 注释截断 → 恒真条件**；**根治=预编译参数化**；辅助=**最小权限库账号、关闭报错、WAF、审计**。
  XSS：成因=**输出未按上下文编码**；根治=**输出编码**；辅助=**CSP、HttpOnly、白名单、DOMPurify**。
  CSRF：成因=**请求缺少不可伪造凭据**；防御=**Token + SameSite + Origin/Referer + 二次验证**。
  关系：**XSS 让 CSRF Token 失效**（脚本在同源内可读 Token），**不是「击穿同源策略」**。

#### Q35 ★★ 文件上传漏洞
- **答**：风险：上传 **webshell** 获得服务器控制权。防御：**白名单校验扩展名与 MIME、检查文件头（魔数）、重命名与随机化、上传目录禁止执行脚本、**上传与访问分离**（独立域名/对象存储）、大小与数量限制、图片二次渲染、病毒扫描

#### Q36 ★★ 越权访问
- **答**：**水平越权**：同权限用户互访数据（改 ID 即可看别人订单）；**垂直越权**：低权限执行高权限操作。防御：**服务端对每次请求做权限校验（不可依赖前端隐藏）、资源属主绑定、统一鉴权拦截器、最小权限、参数不可信、审计**

#### Q37 ★★ 反序列化漏洞
- **答**：原理：**不可信数据被反序列化**，触发可控的对象构造/魔术方法，形成**远程代码执行**。防御：**不反序列化不可信数据、白名单类限制、签名校验、升级组件、最小权限运行、RASP/WAF 兜底**

#### Q38 ★★ 代码审计关注点
- **答**：**输入点**（参数、Header、文件、反序列化）→ **危险函数**（拼接 SQL、命令执行、文件操作、模板渲染）→ **输出点**（是否编码）→ **鉴权点**（每个接口是否校验）→ **敏感信息**（硬编码密钥、日志打印口令）→ **加密与随机数**（是否用安全随机、弱算法）

#### Q39 ★ 邮件安全三件套
- **答**：**SPF** 声明哪些 IP 有权以本域发信；**DKIM** 用域名私钥对邮件签名，收方验签；**DMARC** 结合两者给出**处置策略**（none/quarantine/reject）并汇总报告。加密与签名：**S/MIME（证书体系）、PGP**。

## 七、管理与业务连续性（Q40–Q47）

#### Q40 ★★★ 风险评估
- **答**：要素：**资产、威胁、脆弱性、已有安全措施** → **风险**（口诀：资产遇威胁、借道脆弱性，才成风险）。
  流程：**评估准备 → 风险识别（资产/威胁/脆弱性/已有措施）→ 风险分析（可能性 × 影响）→ 风险评价（与可接受水平比较）**。
  处置四策略：**规避（避免）、降低（缓解）、转移（保险/外包）、接受（自留）**。

#### Q41 ★★★ 等保 2.0
- **答**：五级：**自主、指导、监督（三级，最常见）、强制、专控**。
  定级要素：**受侵害的客体 + 对客体的侵害程度**。
  流程：**定级 → 备案 → 建设整改 → 等级测评 → 监督检查**。
  要求：**技术 5 类（物理、通信网络、区域边界、计算环境、管理中心）+ 管理 5 类（制度、机构、人员、建设、运维）**。
  三级关键项：**双因素身份鉴别、最小权限访问控制、安全审计（日志留存不少于 6 个月）、入侵防范、数据完整性与保密性、集中管控**。

#### Q42 ★★★ BCP / DRP 与指标
- **答**：**BCP 关注业务持续，DRP 关注 IT 灾难恢复，DRP 是 BCP 的子集**。
  **RTO** 允许中断多久（恢复可用）；**RPO** 允许丢多少数据（由备份间隔决定）；**MTD** 最大可容忍中断，**RTO 不得大于 MTD**。
  备份：**全量 / 增量（对上次任意备份）/ 差分（对上次全量）**；要点：**异地存放、加密、定期恢复演练——没演练过的备份等于没有备份**。

#### Q43 ★★ BIA 业务影响分析
- **答**：作用：识别**关键业务与依赖关系**，量化**中断影响**，推导 **RTO/RPO** 与恢复优先级，为 BCP 提供依据。输出：**关键业务清单、依赖的 IT 资源与人员、影响程度分级、恢复优先级**

#### Q44 ★★ 安全管理制度体系
- **答**：四层文件：**一级 方针与策略 → 二级 管理制度 → 三级 操作规程/流程 → 四级 记录与表单**。要点：**覆盖物理、网络、主机、应用、数据、人员、供应链**；**可落地、可考核、定期评审修订**；**发布需审批与宣贯**

#### Q45 ★★ 供应链与外包安全
- **答**：风险：**边界模糊、期限模糊、责任模糊**。控制：**准入评估与安全协议、独立账号禁共享、最小权限与时限自动失效、MFA、操作审计与录屏、网络隔离/跳板机、数据不出域、离场权限回收与设备清退、持续监督**

#### Q46 ★★ 三法要点
- **答**：**《网络安全法》**：等级保护制度、**网络日志留存不少于 6 个月**、关键信息基础设施保护、实名制；**《数据安全法》**：数据分类分级、重要数据目录、数据出境安全评估；**《个人信息保护法》**：**告知同意、最小必要、单独同意、个人权利（查阅复制删除）、跨境规则、处罚**

#### Q47 ★ 安全审计与日志
- **答**：要求：**覆盖关键系统与操作、集中采集、时间同步（NTP）、防篡改、留存不少于 6 个月、定期审计分析**。要素：**时间、来源 IP 与端口、用户身份、行为与结果**。注意：**审计员与系统管理员职责分离**

## 八、安全工程与综合（Q48–Q50）

#### Q48 ★★ 安全开发生命周期与威胁建模
- **答**：阶段：**安全需求 → 安全设计（威胁建模）→ 安全编码 → 安全测试（代码审计/渗透）→ 安全部署 → 安全运维**，每阶段设**评审门禁**。
  **STRIDE**：**仿冒、篡改、抵赖、信息泄露、拒绝服务、权限提升**。
  原则：**最小特权、纵深防御、职责分离、默认拒绝、失效安全、公开设计（Kerckhoffs）、木桶原则**

#### Q49 ★★ CC 与 SSE-CMM
- **答**：**CC** 评估**信息技术产品**安全性，保证级 **EAL1–EAL7**，文档含 **PP（保护轮廓）** 与 **ST（安全目标）**；**SSE-CMM** 评估**安全工程过程能力**，分 **5** 个能力级别。

#### Q50 ★★ 综合案例：被入侵后的整改方案
- **答**（分层写，每层 2 条即可）：
  **技术层**：边界串联 IPS + 旁路 IDS、补 WAF、主机 EDR、日志集中与留存 6 个月、补丁与基线、最小权限与双因素；
  **管理层**：成立应急小组、完善预案与演练、权限复核与离职回收、供应链与外协管控、安全培训与钓鱼演练；
  **监测层**：建立告警分级与值守、威胁情报、定期漏扫与渗透、月度复盘；
  **合规层**：等保测评整改闭环、数据分类分级、事件上报与留痕。

## 九、考前必背的 10 句「万能得分句」

1. **不可否认性的底气**：私钥唯一 + 公钥公开 = 能向第三方（法官）举证。
2. **IDS 的 D 是 Detect**：旁路只告警，物理上拦不住。
3. **MAC 下管理员只打标签配策略**，不逐次放行。
4. **最小特权 = 默认拒绝 + 按需授权 + 定期复核 + 离职回收 + 职责分离**。
5. **SQL 注入治本靠预编译**，关键字过滤是缓解、必被绕过。
6. **XSS 治本靠按上下文输出编码**；CSRF 治本靠不可预测的 Token。
7. **应急响应先抑制再根除**：先止血，别急着重装。
8. **RTO 不得大于 MTD；没演练过的备份等于没有备份。**
9. **风险 = 资产遇威胁、借道脆弱性**；处置四策略：规避、降低、转移、接受。
10. **日志留存不少于 6 个月**，审计要素：时间、来源 IP、用户身份、行为与结果。
