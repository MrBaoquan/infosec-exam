# 🗣️ 简答题实战演练与薄弱点台账

> 这份台账只做一件事：**记录我每次简答题的失分点，并把它变成考前能直接背的清单。**
> 我按考纲重点轮流出题 → 你作答 → 逐点评分 → 失分原因归类 → 汇入复习清单。

## 一、评分规则（每轮固定不变）

| 项目 | 规则 |
|------|------|
| 满分 | 每题 10 分 |
| 给分方式 | **得分点制**：先列本题应当命中的得分点，再逐个对照给分 |
| 单点给分 | 关键词正确 + 因果讲清 = 满分；只堆名词、说不出所以然 = 半分 |
| 文字长度 | 与得分点无关，答得长不等于得分高 |

分档含义：

| 得分 | 档位 | 后续动作 |
|:----:|------|----------|
| 9–10 | 优秀 | 该考点标为已巩固，只做间隔复习 |
| 7–8 | 合格 | 补 1 个失分点，进复习清单但不置顶 |
| 5–6 | 需补强 | 失分点置顶，下一轮以变式题复查 |
| 4 及以下 | 未掌握 | 该考点升级为独立题型页，按七块内容重讲 |

## 二、出题轮转表（保证不偏科）

| 领域 | 高频简答考点 | 已出题 | 平均得分 |
|------|--------------|:------:|:--------:|
| 密码学应用 | 数字签名、数字信封、混合加密、PKI 证书链 | 0 | – |
| 网络防护 | 防火墙/IDS/IPS 选型、VPN 与 IPSec、TLS 握手 | 0 | – |
| 系统与访问控制 | 认证三要素、DAC/MAC/RBAC、最小特权 | 0 | – |
| 恶意代码与应急 | 病毒/蠕虫/木马辨析、应急响应六阶段、取证 | 0 | – |
| 应用安全 | SQL 注入/XSS/CSRF 机理与防御、代码审计 | 0 | – |
| 风险管理与等保 | 风险评估流程、等保 2.0 定级与要求、风险处置四策略 | 0 | – |
| 业务连续性 | BCP/DRP、RTO/RPO、备份策略、容灾等级 | 0 | – |
| 安全工程 | 安全开发生命周期、安全需求、CC/SSE-CMM | 0 | – |

> 出题顺序不是按上表从上到下，而是按**真题出现频率 + 你的失分密度**动态调整：上一轮失分重的领域，下一轮换角度再考。

## 三、演练台账（逐轮追加，只增不改）

| 轮次 | 领域 | 核心考点 | 难度 | 得分 | 一句话失分点 | 归类 |
|:----:|------|----------|:----:|:----:|--------------|:----:|
| 01 | 密码学应用 | 数字签名过程、不可否认性、为何先哈希 | ★★ | – | 待作答 | – |

## 四、失分模式归类（六类，考后重点盯这几类）

| 代号 | 失分模式 | 典型表现 | 累计次数 |
|:----:|----------|----------|:--------:|
| A | 术语混用 | 把「加密」说成「签名」、把「完整性」说成「保密性」 | 0 |
| B | 要点残缺 | 只答正过程，漏掉反向验证或前提条件 | 0 |
| C | 只给结论不讲机理 | 问「为什么」却只答「是什么」 | 0 |
| D | 防护单边 | 只写攻击手法不写防御措施，或只写技术不写管理 | 0 |
| E | 结构松散 | 要点埋在长句里，评分点找不到 | 0 |
| F | 边界不清 | 绝对化表述，不写适用条件与限制 | 0 |

> A 类靠辨析表治，B/E 类靠答题模板治，C/F 类靠「原理一句话解释」治。

## 五、复习清单（只收真正失分过的点）

> 规则：每条都由某轮的具体失分点改写而来，写清「问什么 → 必须答到什么」，考前只看这一节。

- 暂无记录，第一轮作答后开始累积。

## 六、与题型页的联动规则

1. 同一考点在台账里**连续两轮低于 6 分**，就升级为独立题型页（`docs/00-key-memory/` 下新建，按识别信号 → 核心原理 → 通用步骤 → 例题 → 变式 → 易错 → 速记卡七块写）。
2. 题型页负责「怎么答」，本台账负责「我错在哪」，两者互不替代。
3. 每轮结束都要：更新台账 → 更新复习清单 → 更新轮转表得分 → 构建 → 推送到线上。
