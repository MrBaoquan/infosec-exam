# 🗣️ 简答题实战演练与薄弱点台账

> 这份台账只做一件事：**记录我每次简答题的失分点，并把它变成考前能直接背的清单。**
> 我按考纲重点轮流出题 → 你作答 → 逐点评分 → 失分原因归类 → 汇入复习清单。

## 一、评分规则（每轮固定不变）

| 项目 | 规则 |
|------|------|
| 满分 | 每题 10 分 |
| 给分方式 | **得分点制**：先列本题应当命中的得分点，再逐个对照给分 |
| 单点给分 | 关键词正确 + 因果讲清 = 满分；只堆名词、说不出所以然 = 半分 |
| 文字长度 | 与得分点无关，答得长不等于得分高 |

分档含义：

| 得分 | 档位 | 后续动作 |
|:----:|------|----------|
| 9–10 | 优秀 | 该考点标为已巩固，只做间隔复习 |
| 7–8 | 合格 | 补 1 个失分点，进复习清单但不置顶 |
| 5–6 | 需补强 | 失分点置顶，下一轮以变式题复查 |
| 4 及以下 | 未掌握 | 该考点升级为独立题型页，按七块内容重讲 |

## 四、失分模式归类（六类，考后重点盯这几类）

| 代号 | 失分模式 | 典型表现 | 累计次数 |
|:----:|----------|----------|:--------:|
| A | 术语混用 | 把「加密」说成「签名」、把「完整性」说成「保密性」 | 1 |
| B | 要点残缺 | 只答正过程，漏掉反向验证或前提条件 | 1 |
| C | 只给结论不讲机理 | 问「为什么」却只答「是什么」 | 1 |
| D | 防护单边 | 只写攻击手法不写防御措施，或只写技术不写管理 | 0 |
| E | 结构松散 | 要点埋在长句里，评分点找不到 | 0 |
| F | 边界不清 | 绝对化表述，不写适用条件与限制 | 0 |

> A 类靠辨析表治，B/E 类靠答题模板治，C/F 类靠「原理一句话解释」治。

## 五、复习清单（只收真正失分过的点）

> 规则：每条都由某轮的具体失分点改写而来，写清「问什么 → 必须答到什么」，考前只看这一节。

### 密码学应用

- **验签的三连动作** —— 问「B 如何验证签名」时，必须答到：用 A 的**公钥解出签名值中的摘要** → 用**同一哈希算法对报文重算摘要** → **两者比对**，一致才通过。只写「用公钥验证」只能拿一半分。
- **不可否认性的三层机理** —— ① A 的私钥只有 A 有，故只有 A 能产生该签名；② A 的公钥公开，任何第三方都能独立验签；③ 因此 A 抵赖时**能拿到法官/仲裁者面前举证**。对称密钥双方共享，A、B 都能造出同样的密文，无法向第三方举证，所以做不到抗抵赖。
- **先哈希的四条理由** —— ① RSA 只能处理小于模长的数据块，哈希把任意长度压成定长；② 签名运算比哈希慢得多，签摘要才有效率；③ 摘要与原文分离，可只传签名值做存证；④ 哈希的**抗碰撞性**把「完整性」变成「摘要是否一致」这个可比对的问题。注意：**签名不是加密，不存在「签原文会泄露原文」这种说法**。
- **答题严谨性：签名对象要与验证顺序自洽** —— 若签名盖在**明文摘要**上，接收方须**先解密再验签**；若要**先验签后解密**，签名必须盖在**密文**上。答题时用一句话把签名对象交代清楚。
- **一句话区分** —— 加密管「看不看得懂」，签名管「是不是你发的、中途改没改过」。

## 六、与题型页的联动规则

1. 同一考点在台账里**连续两轮低于 6 分**，就升级为独立题型页（`docs/00-key-memory/` 下新建，按识别信号 → 核心原理 → 通用步骤 → 例题 → 变式 → 易错 → 速记卡七块写）。
2. 题型页负责「怎么答」，本台账负责「我错在哪」，两者互不替代。
3. 每轮结束都要：更新台账 → 更新复习清单 → 更新轮转表得分 → 构建 → 推送到线上。
