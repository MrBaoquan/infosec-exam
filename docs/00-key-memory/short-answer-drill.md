## 四、题目与标准答案（逐轮留存，先自测再展开）

### 第 01 轮 · 数字签名与数字信封（得分 8 / 10）

> **原题**：某单位要传送一份采购合同，要求 ① 只有 B 能看懂 ② B 能确认是 A 发的且没被改过 ③ 事后 A 不否认发过、B 不否认收到过。
> （1）A 发出的数据由哪几部分组成，各部分用什么算法、用谁的哪把密钥生成？（2）B 按什么顺序、用什么密钥验证与解密？（3）为什么数字签名能提供不可否认性而对称加密做不到？（4）签名前为什么先做哈希？

<details>
<summary>满分标准答案（点开对照）</summary>

**（1）数据组成**

| 组成 | 生成方式 | 解决的问题 |
|------|----------|-----------|
| 密文 | 用随机**会话密钥（对称算法，如 AES）**加密原文 | 保密性 |
| 数字信封 | 用 **B 的公钥**加密该会话密钥 | 让只有 B 能拿到会话密钥 |
| 数字签名 | 对原文**摘要**用 **A 的私钥**签名 | 身份认证 + 完整性 + 不可否认性 |

**（2）接收方流程**

1. 用 **B 的私钥**解开数字信封，得到会话密钥（若签名盖在明文摘要上，此步先解密再验签）；
2. 用会话密钥解密密文，得到原文；
3. 用 **A 的公钥**解开签名值，得到**摘要 1**；
4. 用**与 A 相同的哈希算法**对原文重算，得到**摘要 2**；
5. **摘要 1 与摘要 2 比对**，一致则确认来源为 A 且内容完整。

**（3）不可否认性机理（三层）**

① A 的私钥**只有 A 持有**，故只有 A 能产生该签名；② A 的公钥**公开**，任何第三方都能独立验签；③ 因此 A 抵赖时，**能拿到法官/仲裁者面前举证**。对称加密双方共享同一把密钥，A、B 都能造出同样的密文，无法向第三方证明是谁造的，所以做不到抗抵赖。

**（4）先哈希的理由**

① RSA 只能处理小于模长的数据块，长报文必须分块，哈希把**任意长度压成定长**，一次签名即可；② 签名运算**远慢于哈希**，签摘要才有实用效率；③ 摘要与原文**分离**，可只传签名值用于存证；④ 哈希的**抗碰撞性**把「完整性」变成「摘要是否一致」这个可比对的问题。
</details>

### 第 02 轮 · 防火墙 / IDS / IPS 定位与选型（得分 2 / 10）

> **原题**：某单位 Web 业务对外开放，边界只有一台包过滤防火墙，运维反馈「网站被拖库了，防火墙日志里一点异常都没有」。
> （1）说清防火墙、IDS、IPS 的能力与部署位置；（2）只靠防火墙为何不足（至少两条），它看不见什么；（3）只加一台选 IDS 还是 IPS，理由与前提条件；（4）拖库流量通常长什么样，为何能绕过防火墙。

<details>
<summary>满分标准答案（点开对照）</summary>

**（1）能力与位置**

| 设备 | 位置 | 深度 | 动作 | 短板 |
|------|------|------|------|------|
| 防火墙 | 边界**串联** | 三/四层 + 连接状态 | 放行 / 拒绝 | 看不见内容，放行的端口就是通道 |
| IDS | **旁路**（SPAN 镜像 / 分光器） | 七层 | 只**告警 + 记录** | 看见了也拦不住 |
| IPS | 链路**串联** | 七层 | **实时阻断** | 误报断业务、自身单点故障 |

**（2）只靠防火墙为何不足**

① 必须放行 80/443，应用层攻击就藏在这些合法会话里；② 不做应用层内容解析，SQL 注入在包头看来完全正常；③ 业务普遍 HTTPS 加密，载荷根本看不到；④ 没有内容级记录与告警，事后无法复盘攻击链。

**（3）选型**

选 **IPS**（拖库需要实时阻断，IDS 只能事后告警），前提四件套：① **Bypass 直通或双机 HA**，故障时链路自动直通；② **误报调优 + 观察期**，先只告警再切阻断；③ **性能与延迟评估**，扛得住峰值流量；④ **日志集中留存 + 值守处置**。若可用性优先或暂无运营人力，则先上 IDS 做基线观察与取证。

**（4）拖库流量形态**

`UNION SELECT`、`information_schema` 探测、大批量 `SELECT`、异常大的响应体、高频访问 `.sql/.bak/.zip`、非工作时段的数据库连接、上行流量突增（数据外传）。绕过原因：**端口合法 + 载荷加密 + 攻击发生在被放行的会话内部**。
</details>

### 第 03 轮 · 等保三级入侵防范与安全审计（得分 7 / 10）

> **原题**：某单位要过等保三级，「入侵防范」与「安全审计」两项要合规，边界只有一台包过滤防火墙。
> （1）为满足入侵防范，边界应串联什么设备、它能做什么防火墙做不到的事？业务不能中断、不能串联时怎么办，代价是什么？（2）还要在哪一侧补什么，才能发现「内网主机已被控制、正主动向外连接」？（3）安全审计要求日志集中留存，写出留存期限与一条合格审计记录的必备要素。

<details>
<summary>满分标准答案（点开对照）</summary>

**（1）边界入侵防范**

串联部署 **IPS**：它做**七层载荷与行为检测**并**实时阻断**；而防火墙只按 IP/端口/协议与连接状态做放行，**不做内容检测**，也因此不产生内容级告警。业务不允许中断时，退一步在交换机**旁路**（镜像/分光）部署 **IDS**，代价是**只能检测与取证、无法实时阻断**，攻击只能事后追溯。

**（2）内网与主机侧补充**

- **流量侧**：核心交换机镜像**东西向**流量接 NIDS，覆盖内网横向移动；边界设备只看南北向。
- **主机侧**：部署 **HIDS/EDR**，监控进程、启动项、注册表与异常外联，而不只是装防病毒。
- **出向侧**：DNS 日志 + 外联行为分析（固定心跳、非常规端口、DGA 域名、威胁情报比对），识别 C2 回连与数据外传。

**（3）日志留存与审计要素**

网络日志留存**不少于 6 个月**（《网络安全法》第二十一条）；一条合格审计记录应包含：**事件时间、来源 IP 与端口、用户身份、操作行为与结果**。工程要求：**NTP 统一时间同步**（保证跨设备时间线可比）、**防篡改与集中存储**。
</details>

### 第 04 轮 · SQL 注入 / XSS / CSRF 三件套（得分 4.5 / 10）

> **原题**：某系统登录页与查询接口被判定同时存在 SQL 注入与存储型 XSS。
> （1）SQL 注入的成因？（2）举最小载荷并解释为何生效、如何拖库？（3）至少三层防御并指出根治手段？（4）SQL 注入与 XSS 的本质区别（注入对象/执行位置/危害/防御）？（5）已有 CSRF Token，为何存在 XSS 时仍失效？

<details>
<summary>满分标准答案（点开对照）</summary>

**（1）成因**：后端用**字符串拼接**构造 SQL，用户输入与代码共用同一条解析通道——危险根因不是「有特殊字符」，而是**代码与数据没有分离**。

**（2）载荷与机理**

```sql
-- 原语句：select * from users where username = '$u' and password = '$p'
-- 输入：admin' --
select * from users where username = 'admin' -- ' and password = '$p'
```

三步生效：`'` **闭合**字符串边界 → `-- `（MySQL 中 `--` 后须跟空格，`#` 也可）**注释掉**密码条件 → 查询退化为「用户名对就放行」。拖库：`order by n` 探列数 → `union select 1,2,3` 找回显位 → `union select username,password,4 from users`；无回显时用布尔/时间/报错**盲注**。

**（3）三层防御 + 根治**

| 层 | 措施 |
|:--:|------|
| 代码层（**根治**） | **预编译 / 参数化查询**：语句模板先编译，参数只作数据绑定，永不参与语法解析 |
| 权限与配置层 | 数据库**最小权限账户**、关闭详细报错、禁用危险函数 |
| 检测与兜底层 | WAF 虚拟补丁、SQL 审计日志与告警 |

关键字/正则过滤只能对抗症状：`union/**/select`、大小写混写、等价表达式、编码变形都能绕过。

**（4）四维对比**

| 维度 | SQL 注入 | XSS |
|------|----------|-----|
| 注入对象 | 数据库 SQL 解释器 | 浏览器 HTML/JS 解释器 |
| 执行位置 | **服务端** | **客户端**（后端只是未编码的转发者） |
| 危害 | 拖库、改库、删库、越权 | 盗 Cookie/Session、钓鱼、篡改页面、蠕虫 |
| 防御 | 预编译参数化、最小权限、关报错 | **按上下文输出编码**、CSP、HttpOnly、白名单 |

**（5）XSS 下 CSRF 为何失效**

CSRF 防护假设「攻击者读不到页面内容，因而拿不到 Token」。XSS 脚本运行在目标站点**同源上下文**内，可直接读取页面中的 Token 并携带发出请求 → Token 校验失去意义。**注意：这不是「击穿同源策略」**，同源策略只限制读取响应、从不阻止请求发出，CSRF 本就不需要击穿它。
</details>

## 六、复习清单（只收真正失分过的点）

> 规则：每条都由某轮的具体失分点改写而来，写清「问什么 → 必须答到什么」，考前只看这一节。

### 通用答题纪律（跨领域，最先看）

- **先数问数，再动笔**：题干有几问就分几段写，编号对应。**整问漏答的代价远大于答错**——第 02 轮就是靠这个丢掉 7 分。
- **名词题必须落到「位置 + 深度 + 动作」**：只写「IDS 是入侵检测系统」得 0 分，写「IDS 旁路部署、分析七层、只告警不阻断」才得分。
- **每答一个机制，补一句「所以它能解决/解决不了什么」**：这是 C 类失分的通用解药。
- **写完自查矛盾**：同一段里出现两句互相打脸的结论（先写「IDS 能阻断」、后写「IDS 只能检测」），阅卷老师只会看到错的那句。**交卷前 30 秒专扫这个。**

### 密码学应用

- **验签的三连动作** —— 问「B 如何验证签名」时，必须答到：用 A 的**公钥解出签名值中的摘要** → 用**同一哈希算法对报文重算摘要** → **两者比对**，一致才通过。只写「用公钥验证」只能拿一半分。
- **不可否认性的三层机理** —— ① A 的私钥只有 A 有，故只有 A 能产生该签名；② A 的公钥公开，任何第三方都能独立验签；③ 因此 A 抵赖时**能拿到法官/仲裁者面前举证**。对称密钥双方共享，A、B 都能造出同样的密文，无法向第三方举证，所以做不到抗抵赖。
- **先哈希的四条理由** —— ① RSA 只能处理小于模长的数据块，哈希把任意长度压成定长；② 签名运算比哈希慢得多，签摘要才有效率；③ 摘要与原文分离，可只传签名值做存证；④ 哈希的**抗碰撞性**把「完整性」变成「摘要是否一致」这个可比对的问题。注意：**签名不是加密，不存在「签原文会泄露原文」这种说法**。
- **答题严谨性：签名对象要与验证顺序自洽** —— 若签名盖在**明文摘要**上，接收方须**先解密再验签**；若要**先验签后解密**，签名必须盖在**密文**上。答题时用一句话把签名对象交代清楚。
- **一句话区分** —— 加密管「看不看得懂」，签名管「是不是你发的、中途改没改过」。

### 网络防护

- **🔴 IDS / IPS 分水岭（已错两次，置顶）** —— **IDS 的 D 是 Detect**：旁路、只告警、**物理上拦不住**；**IPS 的 P 是 Prevent**：串联、能实时阻断。只要把「阻断」写给 IDS 就直接扣分；前后两句自相矛盾再扣一次。心里默念：**不在链路上，就没有阻断权。**
- **边界只挡南北向** —— 内网主机被控后的横向移动与 C2 回连属于**东西向 / 出向**流量：核心交换镜像接 **NIDS**、主机侧部署 **HIDS/EDR**、出向做 **DNS 日志与外联行为分析**。**只装防病毒不够**，它靠特征查杀，对加密外联与合法进程滥用无能为力。
- **日志留存硬指标** —— 网络日志留存**不少于 6 个月**（《网络安全法》第二十一条）；一条合格审计记录要有：**时间、来源 IP 与端口、用户身份、行为与结果**；工程上还需 **NTP 统一时间 + 防篡改 + 集中存储**。
- **三问定位法** —— 任何边界设备都按「串联还是旁路 → 看四层还是七层 → 动作是放行/告警/阻断」三栏填满。这是防火墙 / IDS / IPS / WAF / 蜜罐通用模板。
- **选型必答「前提四件套」** —— Bypass 直通或双机 HA、误报调优与观察期、性能与延迟评估、日志集中留存与值守处置。**不写前提，选型题最多一半分。**
- **绕过防火墙的三件套** —— 合法端口（80/443）+ 加密流量（HTTPS）+ 应用层载荷（SQL 注入藏在正常请求里）。
- **术语：拖库** —— 攻击者把业务库整表或整库导出拿走。危害在「读」，而防火墙只擅长管「通不通」，所以**端口策略全对也可能被拖库**。
- **攻击流量特征** —— `UNION SELECT`、`information_schema` 探测、大批量 `SELECT`、异常大响应体、高频访问 `.sql/.bak`、非工作时段的库连接、上行突增。

### 应用安全

- **🔴 区分「根治」与「缓解」（第 04 轮吃亏点）** —— SQL 注入的根治**只有预编译/参数化**；「过滤关键字、对拼好的 SQL 做正则检查」属于缓解，且必被绕过。答防御题时**先写根治层，再写缓解层**，顺序反了也扣分。
- **为什么参数化是根治** —— 语句模板先编译成语法树与执行计划，参数只作为**值绑定**，不再参与词法/语法解析。**这是消除攻击面，不是提高对抗强度。**
- **SQL 注入载荷三要素** —— 闭合（`'`）→ 注释截断（`-- ` 后带空格，或 `#`、`/**/`）→ 恒真条件（`or 1=1`）。**只贴载荷不解释机理拿不到分。**
- **拖库三步** —— `order by n` 探列数 → `union select 1,2,3` 找回显位 → `union select ... from users` 取数据；无回显时用布尔/时间/报错**盲注**。
- **XSS 只在客户端执行** —— 后端只是「没做输出编码的转发者」，不在后端执行脚本。防御主场在**输出侧**：HTML/属性/JS/URL 按上下文编码 + **CSP** + **HttpOnly** + 富文本白名单净化（DOMPurify）。
- **CSRF Token 防不了 XSS** —— Token 防「伪造请求」，防不了同源脚本读取页面里的 Token。
- **XSS 不是「击穿同源策略」** —— 同源策略只限制**读取响应**、从不阻止请求发出；XSS 绕过的是「攻击者读不到页面内容」这条假设，它**本来就在同源内部**。XSS 危害等级高于 CSRF。
- **三句压舱石** —— 注入看「谁在执行字符串」，跨站看「请求是谁发出的」；SQL 注入治本靠预编译、XSS 靠编码、CSRF 靠 Token。
