# 🚀 考前冲刺 · 填空与简答标准答案速查

> 用法：**不要通读**。先看第一节的 10 条，再看第二、三节的得分点词，最后回到第四节辨析表扫一遍。
> 填空题扣分只有两种原因：**术语不规范**、**数字记错**。简答题扣分只有一个原因：**只写了一句没有展开**。

## 一、考前 30 分钟只看这 10 条

1. **数字签名**：对**摘要**用**自己私钥**签，对方用**你的公钥**验；提供**完整性 + 身份认证 + 不可否认**，不提供保密性。
2. **数字信封**：用**对方公钥**加密**会话密钥**；解决「对称密钥怎么安全送过去」。
3. **不可否认**的底气：私钥唯一 + 公钥公开 = **能向第三方（法官）举证**；对称密钥双方共享，做不到。
4. **IDS 的 D 是 Detect**（旁路、只告警、拦不住）；**IPS 的 P 是 Prevent**（串联、能阻断、怕误报与单点故障）。
5. **SQL 注入治本 = 预编译（参数化）**；关键字过滤是缓解，必被绕过。
6. **XSS 治本 = 按上下文输出编码**（+ CSP、HttpOnly）；CSRF 治本 = **不可预测的 Token**（+ SameSite、Origin 校验、二次验证）。
7. **DAC 属主给钥匙 / MAC 系统比标签 / RBAC 权力挂岗位**；MAC 下管理员只**打标签配策略**，不逐次放行。
8. **最小特权 = 默认拒绝 + 按需授权 + 定期复核 + 离职 24h 内回收 + 职责分离**。
9. **应急响应六阶段**：准备 → 检测 → 抑制 → 根除 → 恢复 → 跟踪（PDCERF）。
10. **日志留存不少于 6 个月**（《网络安全法》第二十一条）；一条审计记录要有**时间、来源 IP、用户身份、行为与结果**。

## 一·五、考卷形态与时间分配（开考前先想清楚这些）

**上午 · 基础知识**：75 道单选，每题 1 分，满分 75，通常 45 分及格。

**下午 · 应用技术**：**5 道大题，每题 15 分，满分 75，通常 45 分及格**；机考打字作答。
（批次、时长、合格线可能调整，以准考证与官方通知为准。）

五道大题通常固定为这五种形态，每题内部再拆 **3–5 个小问，每问 2–5 分**：

| 题号 | 形态 | 常见小问 | 拿分要点 |
|:----:|------|----------|----------|
| 一 | 密码学应用 | 算 RSA/哈希、选算法、写收发流程 | 写**过程**，不只写结果 |
| 二 | 网络安全配置 | 补防火墙规则、填 IPSec 参数、抓包分析、子网计算 | 抄格式，缺项就扣 |
| 三 | Web 安全 | 指漏洞行 + 写修复代码 + 说机理 | 一行一处，别混着写 |
| 四 | 安全管理 | 等保定级、风险评估、ALE 计算、应急流程 | 背流程顺序，分点写 |
| 五 | 综合分析 | 攻击链还原、分层整改方案 | 技术/管理/监测/合规四层写 |

**每题 15 分不等于 15 分都难拿**：通常 6–8 分是「术语 + 列措施」的送分点，4–6 分是配置/修复应用，2–4 分是计算或设计。**先把送分点拿满，再攻计算。**

**时间分配（按 150 分钟算）**：每题 25 分钟 + 留 25 分钟检查。
每题内部：**读题 3 分钟（先数清几问、圈出动词「简述/说明/给出/计算」）→ 列得分点提纲 3 分钟 → 作答 15 分钟 → 回查 4 分钟**。

**机考三个实操提醒**

1. **分点用编号**（①②③ 或 1. 2. 3.），阅卷按点找词；
2. **计算题写过程**，只有结果容易零分；
3. **不认识的问也别空着**：写「预防—检测—响应」三层框架的通用措施，通常能蹭到点。

## 二、数字与参数速记表（填空题必考）

### 密码算法

| 算法 | 关键参数 | 一句话定位 |
|------|----------|-----------|
| DES | 分组 **64** 位，密钥 **56** 位，**16** 轮 | 已不安全，密钥太短 |
| 3DES | 密钥 168 位（有效 112） | DES 的三次迭代，慢 |
| AES | 分组 **128** 位；密钥 128/192/256；轮数 **10/12/14** | 现行对称主力 |
| SM1 | 分组 128、密钥 128，**不公开** | 硬件实现 |
| SM4 | 分组 **128** 位，密钥 **128** 位，**32** 轮 | 国产分组密码 |
| SM3 | 输出 **256** 位 | 国产哈希 |
| SM2 | 基于**椭圆曲线（ECC）**，密钥 **256** 位 | 国产公钥算法，签名/加密/密钥交换 |
| SM9 | **标识密码**（以身份标识为公钥） | 免证书体系 |
| ZUC | 序列密码，用于 4G | 祖冲之算法 |
| MD5 / SHA-1 / SHA-256 | 输出 **128 / 160 / 256** 位 | MD5、SHA-1 已不推荐 |
| RSA | 基于**大整数分解**；密钥建议 **不低于 2048** 位 | 慢，只用来加密密钥或签名 |
| DH | 基于**离散对数**；不认证身份 | 易受**中间人攻击**，须配证书 |

### 协议与端口

| 项 | 值 |
|----|-----|
| IPSec：AH / ESP | 协议号 **51 / 50**；AH 只认证不加密，ESP 提供加密 |
| IPSec 模式 | **传输模式**保护载荷（主机到主机）；**隧道模式**保护整个 IP 包（网关到网关） |
| IKE / NAT 穿越 | UDP **500** / UDP **4500** |
| Kerberos | **88**（TCP/UDP），KDC 含 AS 与 TGS，签发 **TGT** |
| RADIUS | 认证 **1812** / 计费 **1813** |
| HTTPS / SSH / Telnet | 443 / 22 / 23 |
| 802.1X | 基于**端口**的接入认证，配合 EAP + RADIUS |

### 管理与标准

| 项 | 值 |
|----|-----|
| 等保 2.0 级别 | **五级**：自主、指导、监督（**三级**）、强制、专控 |
| 等保 2.0 要求分类 | 技术 **5** 类（物理、通信网络、区域边界、计算环境、管理中心）+ 管理 **5** 类（制度、机构、人员、建设、运维） |
| 等保定级要素 | **受侵害的客体** + **对客体的侵害程度** |
| 日志留存 | **不少于 6 个月** |
| 容灾能力等级（GB/T 20988） | **1–6 级** |
| CC 评估保证级 | **EAL1–EAL7** |
| SSE-CMM 能力级别 | **5** 级 |
| 应急响应阶段 | **6** 阶段（PDCERF） |
| 风险处置策略 | **4** 种：规避（避免）、降低（缓解）、转移、接受 |
| 备份类型 | 全量 / 增量（对上次**任意**备份）/ 差分（对上次**全量**） |
| RTO / RPO / MTD | 恢复时间 / 恢复点 / 最大可容忍中断；**RTO 不得大于 MTD** |

## 三、高频简答题型 · 得分点速查（按领域）

> 每条开头是「题干长什么样」，破折号后是**必须写出的得分点词**。答的时候就照着数的个数写。

### ① 密码学

**1. 数字信封 + 数字签名（★★★）**
- 题干：要保密 + 认证 + 抗抵赖；问「数据由哪几部分组成」「接收方怎么处理」
- 得分点：① 原文用**会话密钥对称加密**（保密）② 会话密钥用**对方公钥**封装（数字信封）③ 原文**摘要**用**发送方私钥**签名（认证+完整+抗抵赖）④ 接收方：**自己私钥解信封 → 解密密文 → 对方公钥验签 → 重算摘要比对**
- 口诀：**密钥永远反向用；验签三连「解—算—比」。**

**2. 为什么用混合加密（★★）**
- 得分点：① 对称算法**快**，适合大数据量 ② 非对称算法**密钥分发安全**，但**慢**、且只能加密小于模长的数据 ③ 所以「对称加密数据 + 非对称保护密钥」兼得两者优点
- 口诀：**对称管数据，非对称管钥匙。**

**3. 哈希函数的作用与性质（★★）**
- 得分点：① **单向不可逆** ② **抗碰撞**（不同输入不同输出）③ **定长输出** ④ **雪崩效应**（改一位输出全变）⑤ 用途：完整性校验、口令存储（加盐）、数字签名、消息认证码
- 口诀：**单向、定长、抗碰撞、会雪崩。**

**4. PKI 与数字证书（★★）**
- 得分点：① 组成：**CA、RA、证书库、CRL/OCSP、时间戳** ② 证书格式 **X.509** ③ 证书把**公钥与身份绑定**，由 CA 用**私钥签名** ④ 验证链：签名有效 → 未过期 → 未被吊销（查 CRL/OCSP）→ 信任链到根 CA
- 口诀：**CA 给公钥发身份证，验签看三样：签名、有效期、吊销。**

**5. 对称 vs 非对称（★★）**
- 对比：密钥管理（1 把 vs 一对）、速度（快 vs 慢）、用途（数据加密 vs 密钥分配与签名）、可否抗抵赖（否 vs 是）

### ② 网络防护

**6. 防火墙 / IDS / IPS（★★★）**
- 三问定位：**串联还是旁路 → 四层还是七层 → 放行/告警/阻断**
- 防火墙：串联边界、三四层+状态、放行或拒绝、看不见内容
- IDS：**旁路**（镜像/分光）、七层、**只告警**、拦不住
- IPS：**串联**、七层、**实时阻断**、怕误报与单点故障
- 选型必答前提：**Bypass/HA、误报调优与观察期、性能与延迟评估、日志集中与值守**

**7. IPSec VPN（★★）**
- 得分点：① **AH（51）**只认证不加密，**ESP（50）**可加密 ② **传输模式**保护载荷、**隧道模式**保护整个 IP 包 ③ 由 **IKE** 协商 SA（UDP 500）④ 只能用于 IP 层，对应用透明

**8. TLS / HTTPS（★★）**
- 得分点：① 握手协商**协议版本、密码套件、随机数** ② 用**证书验证服务器身份**并交换密钥（ECDHE 前向安全）③ 之后用**对称会话密钥**加密应用数据 ④ 提供保密性、完整性、身份认证

**9. 无线安全（★★）**
- 得分点：① WEP 用 **RC4 + 24 位 IV**，IV 重用导致易破解 ② WPA 用 **TKIP + MIC** ③ WPA2（802.11i）用 **CCMP/AES** ④ WPA3 用 **SAE** 抗离线字典 ⑤ 企业级用 **802.1X + EAP + RADIUS**

### ③ 系统与访问控制

**10. 访问控制三模型（★★★）**
- DAC：**资源属主**自主授权可转授（ACL、权限位）；适合小范围、变动少
- MAC：**系统**按「主体标签 vs 客体密级」强制判定，管理员只打标签配策略；BLP **不上读、不下写**；能防特洛伊木马
- RBAC：权限打包给**角色**，用户通过角色获得；适合人员频繁变动、可做**职责分离**
- 口诀：**DAC 属主给钥匙，MAC 系统比标签，RBAC 权力挂岗位。**

**11. 最小特权落地（★★）**
- 动作化：**默认拒绝 → 按需授权（双签审批）→ 定期复核（季度/半年）→ 离职转岗 24h 内回收 → 职责分离 SoD → 特权账号单管单独审计**

**12. 认证三要素与双因素（★★）**
- 三要素：**你知道什么（口令）／你拥有什么（令牌、证书、U 盾）／你是什么（生物特征）**
- 双因素 = 从**不同类别**里各取一种；同类别两样（口令 + 密保问题）不算
- 协议辨析：**PAP 明文**；**CHAP 三次握手、挑战应答、不传口令本身**；**RADIUS 集中认证**；**Kerberos 基于对称密钥、TGT 票据、单点登录**

### ④ 恶意代码与应急

**13. 病毒 / 蠕虫 / 木马（★★★）**
- 病毒：**寄生**在宿主文件、**需用户触发**、具传染性
- 蠕虫：**独立运行、自主传播**、利用漏洞或弱口令、可耗尽网络带宽
- 木马：**伪装正常程序**、以**远程控制/窃密**为目的、通常不自我复制
- 补充：后门、僵尸网络、Rootkit（隐藏自身）、逻辑炸弹（条件触发）、间谍软件

**14. 应急响应六阶段（★★★）**
- **准备 → 检测 → 抑制 → 根除 → 恢复 → 跟踪（总结）**（PDCERF）
- 要点：抑制阶段先**止损**（隔离、断网、封禁），**不要急着重装**；取证遵循**及时性、完整性、合法性、只读性**，先**固定易失数据**（内存、连接、日志）再断电

**15. 恶意代码防护手段（★★）**
- **特征码检测**（已知）、**行为/启发式检测**（未知变种）、**沙箱动态分析**、**白名单**（工控常用）、补丁与最小权限、终端准入

### ⑤ 应用安全

**16. SQL 注入 / XSS / CSRF（★★★）**
- 一句话分开：**注入看「谁在执行字符串」，跨站看「请求是谁发出的」**
- SQL 注入：成因=代码与数据未分离；载荷三要素=**闭合 → 注释截断 → 恒真条件**；根治=**预编译参数化**；辅助=最小权限、关闭报错、WAF、审计
- XSS：成因=输出未编码；根治=**按上下文输出编码**；辅助=**CSP、HttpOnly、白名单、DOMPurify**
- CSRF：成因=请求缺少不可伪造凭据；防御=**Token + SameSite + Origin/Referer + 二次验证**
- 关系：**XSS 让 CSRF Token 失效**——脚本在同源内可直接读 Token（**不是「击穿同源策略」**）

**17. 数据库安全（★★）**
- 措施：最小权限分账号、**敏感字段加密/脱敏**、审计与行为基线、**禁止明文口令**（加盐哈希）、备份加密与异地存放、防注入

### ⑥ 管理与业务连续性

**18. 风险评估（★★★）**
- 要素：**资产、威胁、脆弱性、已有安全措施** → **风险**
- 流程：**评估准备 → 风险识别（资产/威胁/脆弱性/已有措施）→ 风险分析 → 风险评价**
- 处置四策略：**规避（避免）、降低（缓解）、转移（保险/外包）、接受（自留）**
- 口诀：**资产遇威胁、借道脆弱性，才成风险。**

**19. 等保 2.0（★★★）**
- 五级：自主、指导、**监督（三级）**、强制、专控
- 定级要素：**受侵害客体 + 侵害程度**
- 要求：技术 **5** 类 + 管理 **5** 类
- 三级关键项：身份鉴别（双因素）、访问控制（最小权限）、**安全审计（留存不少于 6 个月）**、入侵防范、数据完整性与保密性、集中管控

**20. BCP / DRP 与指标（★★★）**
- BCP 关注**业务持续**，DRP 关注**IT 灾难恢复**，DRP 是 BCP 的子集
- **RTO**：允许中断多久（恢复到可用）；**RPO**：允许丢多少数据（备份间隔决定）；**MTD**：最大可容忍中断；**RTO 不得大于 MTD**
- 备份：**全量 / 增量（对上次任意备份）/ 差分（对上次全量）**；异地存放、定期恢复演练（**没演练过的备份等于没有备份**）

### ⑦ 安全工程

**21. 安全开发生命周期（★★）**
- 得分点：**安全需求 → 安全设计（威胁建模）→ 安全编码 → 安全测试（渗透/代码审计）→ 安全部署 → 安全运维**；每个阶段有**评审门禁**
- 常见原则：**最小特权、纵深防御、职责分离、默认拒绝、失效安全、公开设计（Kerckhoffs）、木桶原则**

**22. CC / SSE-CMM（★★）**
- **CC**：评估信息技术产品安全性，保证级 **EAL1–EAL7**；文档包括 **PP（保护轮廓）** 与 **ST（安全目标）**
- **SSE-CMM**：评估**安全工程过程能力**，分 **5** 个能力级别

### ⑧ 云、工控、邮件

**23. 云安全责任共担（★★）**
- 边界随服务模式移动：**IaaS** 用户负责**操作系统及以上**；**PaaS** 用户负责**应用与数据**；**SaaS** 用户主要负责**数据与账号**；厂商负责**虚拟化及以下基础设施**

**24. 工控安全（★★）**
- 特点：**协议无认证**（Modbus/DNP3）、**可用性优先**、生命周期长、补丁难打
- 措施：**白名单**（应用/主机）、**单向隔离网关**、**纵深防御分区**、资产测绘、**避免在生产网做扫描**

**25. 邮件安全三件套（★★）**
- **SPF**：声明哪些 IP 有权以本域发信；**DKIM**：用域名私钥对邮件签名，收方验签；**DMARC**：结合两者给出**策略**（none/quarantine/reject）并汇总报告
- 加密与签名：**S/MIME**（证书体系）、**PGP**

## 四、易混辨析一句话（考前扫一遍）

| A | B | 一句话分开 |
|---|---|-----------|
| 加密 | 签名 | 加密保**看不懂**（用对方公钥）；签名保**赖不掉**（用自己私钥） |
| 完整性 | 不可否认 | 完整性=**没被改**；不可否认=**能向第三方举证是谁做的** |
| 认证 | 授权 | 认证答「你是谁」；授权答「你能干什么」 |
| 对称 | 非对称 | 一把钥匙 vs 一对钥匙；快 vs 慢；不能抗抵赖 vs 能抗抵赖 |
| 数字信封 | 数字签名 | 前者送**密钥**（对方公钥加密）；后者证**来源**（自己私钥签名） |
| 防火墙 | IPS | 防火墙管**通不通**（三四层）；IPS 管**内容坏不坏**（七层，串联） |
| IDS | IPS | 旁路只**告警** vs 串联能**阻断**；D=Detect，P=Prevent |
| 漏洞 | 威胁 | 漏洞是**自身的弱点**；威胁是**外部可能利用它的人和事** |
| 风险 | 漏洞 | 风险 = 资产 × 威胁 × 脆弱性；有漏洞不等于有风险 |
| 病毒 | 蠕虫 | 病毒**要宿主、要人点**；蠕虫**能自己跑、自己传** |
| 木马 | 后门 | 木马是**伪装的外壳**；后门是**留下的通道**，常由木马投放 |
| 应急抑制 | 根除 | 抑制=**先止血**（隔离断网）；根除=**去病根**（清马打补丁） |
| RTO | RPO | RTO 容忍**停多久**；RPO 容忍**丢多少** |
| 增量备份 | 差分备份 | 增量对**上次任意备份**；差分对**上次全量** |
| BCP | DRP | BCP 保**业务**；DRP 保 **IT**；DRP 属于 BCP |
| DAC | MAC | 属主**自主**给钥匙 vs 系统**强制**比标签 |
| MAC | RBAC | 按**密级标签** vs 按**岗位角色** |
| 等保三级 | 四级 | 三级=**监督**保护级；四级=**强制**保护级 |
| XSS | CSRF | XSS 让**脚本在别人页面跑**；CSRF 让**浏览器替攻击者发请求** |
| 同源策略 | CSRF 防护 | 同源策略只限制**读响应**，不阻止**发请求**，所以它不防 CSRF |

## 六、简答题三条铁律（今天就能用上）

1. **先数问数再动笔**：题干几问就分几段，编号对应。漏答一整问，比答错更致命。
2. **每段第一句给结论词**，第二句补「所以能解决什么/解决不了什么」。阅卷老师只找得分点词。
3. **交卷前 30 秒专扫矛盾**：同一段里不能出现两句互相打脸的结论。
