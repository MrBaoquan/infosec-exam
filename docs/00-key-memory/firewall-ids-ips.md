# 题型 04 · 防火墙 / IDS / IPS 定位与选型

> **本次原题**：某单位 Web 业务对外开放，边界只有一台包过滤防火墙，运维反馈「网站被拖库了，防火墙日志里一点异常都没有」。请说明防火墙 / IDS / IPS 的能力与部署位置、只靠防火墙为何不足、预算只够加一台时选谁（含前提条件），以及拖库流量通常长什么样。
> **答案**：防火墙串联在边界、只看到三四层、动作是放行/拒绝；IDS **旁路**、看到七层、**只告警不阻断**；IPS **串联**、看到七层、**实时阻断但自身是单点故障**。加设备选 **IPS**，前提是 **Bypass/HA + 误报调优 + 性能评估 + 有人值守**。

## 一、识别信号（看到这些就是这类题）

- 题干出现 **部署位置** 类字眼：串联、旁路、镜像口、分光器、DMZ、内外网之间、核心交换旁。
- 出现 **能力边界** 类字眼：只能告警、能实时阻断、误报、性能瓶颈、单点故障。
- 出现 **选型/预算** 类字眼：只够买一台、优先保证业务连续、要不要上 IPS。
- 出现 **等保条款**：入侵防范、边界防护、安全审计、集中管控。
- 出现 **现象自相矛盾**：被入侵了但日志干净 —— 说明攻击走了「合法端口 + 加密 + 应用层」的通道。

## 二、核心原理（3 分钟真正搞懂）

三台设备不是三个功能清单，而是同一个东西的三种配置：**在链路的哪个位置、把内容看多深、能对流量动什么手**。

- 位置决定**它能不能拦住**：旁路只能看（复制出来的流量），串联才能卡住。
- 深度决定**它看不看得懂**：四层只看信封（谁寄给谁、走哪个门），七层才拆开看信的内容。
- 动作决定**它的风险**：只看不动 = 零风险零收益；能动就必然带来「误伤」和「自己挂了怎么办」。

一句话原理：**防线不是越贵越好，而是「它的失败方式」你要能承受。** 串联设备的失败方式是断网，旁路设备的失败方式是看着被打。

## 三、通用解题步骤（照着套，5 步）

1. **先定题型**：问的是「各设备干什么」还是「该买哪个」。前者答能力表，后者答选型 + 前提。
2. **三问列表**：对每台设备写出「串联/旁路 → 四层/七层 → 放行/告警/阻断」。三栏填满就拿到了这道题一半的分。
3. **找「看不见什么」**：加密流量（HTTPS）看不见、被放行端口里的应用层攻击看不见、内网东西向流量看不见、内部人员滥用看不见。
4. **选型先写失败方式**：串联 = 单点故障 + 误报断业务；旁路 = 拦不住。再判断该业务能不能承受。
5. **必须补前提**：Bypass/双机 HA、误报调优与观察期、性能与延迟评估、日志集中留存与值守处置。**不写前提，选型题最多给一半分。**

## 四、本题完整解答

**（1）能力与部署位置**

| 设备 | 部署位置 | 检测深度 | 处置动作 | 短板 |
|------|----------|----------|----------|------|
| 防火墙 | 边界**串联**（内外网之间、DMZ 前后、内网分区之间） | 三/四层：IP、端口、协议、连接状态 | 放行或拒绝 | 只管「通不通」，看不见内容；它放行的端口就是攻击通道 |
| IDS | **旁路**（SPAN 镜像口 / 分光器 TAP） | 七层：载荷特征 + 异常行为 | 记录、告警 | 看见了也拦不住，只能事后追溯 |
| IPS | 链路**串联** | 七层 | 实时阻断 | 误报即断业务，自身成为单点故障 |

**（2）只靠防火墙为何不足**

1. 防火墙必须**放行对外服务端口**（80/443），应用层攻击正好藏在这些合法会话里；
2. 它**不做应用层内容解析**，SQL 注入、越权查询在包头看来完全正常；
3. 现在业务普遍是 **HTTPS 加密流量**，防火墙连载荷都看不到；
4. 没有**内容级记录与告警**，出了事无法复盘攻击链。

**（3）只加一台的选型**

选 **IPS**：拖库需要**实时阻断**，IDS 只能事后告警。前提条件：

- **Bypass（直通）或双机 HA**：设备故障时链路自动直通，业务不中断；
- **误报调优 + 观察期**：先以「只告警」模式跑一两周，规则稳定后再切阻断；
- **性能与延迟评估**：串联设备必须扛住峰值流量与并发；
- **日志集中留存 + 值守处置**：告警必须有人接、有流程走。

补充答法：若业务可用性压倒一切或暂无运营人力，则先上 **IDS** 做基线观察与取证，再演进到 IPS。

**（4）拖库流量长什么样**

`UNION SELECT`、`information_schema` 探测、大批量 `SELECT`、异常大的响应体、同一来源高频访问 `.sql/.bak/.zip` 路径、非工作时段的数据库端口连接、上行流量突增（数据外传）。它绕过防火墙的原因：**端口合法 + 载荷加密 + 攻击发生在被放行的会话内部**。

## 五、变式训练（先自己做，再展开答案）

<details>
<summary>变式 1：为什么 IPS 更"强"却常常不敢开阻断？</summary>

因为 IPS 串联在链路中，**误报的代价是直接切断正常业务**，而串联设备自身故障会导致整条链路中断。所以工程上要求：先观察模式跑基线、配 Bypass/HA、只对高置信规则开阻断、并保留一键回退。功能越强，越需要配套的可用性保障。
</details>

<details>
<summary>变式 2：某内网要做等保三级「入侵防范」，怎么设计边界与审计？</summary>

边界串联部署**下一代防火墙**（访问控制 + 应用识别）并在关键链路**串联 IPS** 做入侵阻断；在核心交换做**流量镜像接入 IDS**，用于告警与取证；主机侧部署 **HIDS** 补足内网东西向与主机层行为；日志统一送**日志审计系统**集中留存（满足留存期要求）；所有设备策略、告警、处置记录纳入安全运营流程。
</details>

<details>
<summary>变式 3：IDS 部署在旁路，为什么还要给它喂"全部流量"？</summary>

因为旁路设备只能分析它收到的镜像流量，镜像不全会直接导致漏报。工程上要求镜像口覆盖**双向流量**、包含**南北向与东西向**关键链路，并确认镜像口不丢包（流量超过镜像口带宽会静默丢包，这是 IDS 漏报的常见工程原因）。
</details>

<details>
<summary>变式 4：为什么"防火墙放行了 443"不等于"安全了"？</summary>

443 只保证传输加密，不保证会话内的请求是善意的。SQL 注入、越权访问、恶意文件上传都在 443 里正常完成。要发现它们必须靠**七层检测**（IPS/WAF/代码层校验）而不是端口策略。
</details>

## 六、易错点与陷阱

- **只写设备全称**：写「IDS 是入侵检测系统」等于没答，必须写出「旁路 + 七层 + 只告警」。
- **把 IDS 说成能阻断**：IDS 旁路部署，物理上无法阻断流量（除非配合联动封禁，且属于额外机制）。
- **把 IPS 部署在旁路**：旁路只能看不能拦，IPS 的价值就在于串联。
- **说防火墙能过滤 SQL 注入**：传统包过滤/状态检测不行；只有带应用识别与 IPS 模块的 NGFW/或 WAF 才能做。
- **选型忘记前提**：只写「选 IPS 因为能阻断」，不写 Bypass/HA/误报调优，直接扣一半。
- **忽略「拖库」的本质是「读」**：拖库不需要打通新端口，它借的是已经放行的通道，所以「端口策略全对」也可能被拖库。

## 七、考点速记卡（复习只看这一块）

**三问定设备**：串还是并 → 四层还是七层 → 放行/告警/阻断。

| 设备 | 位置 | 深度 | 动作 | 失败方式 |
|------|------|------|------|----------|
| 防火墙 | 串联（边界/DMZ/分区） | 三、四层 + 状态 | 放行 / 拒绝 | 看不见内容，放行的端口成为通道 |
| IDS | 旁路（镜像/分光） | 七层 | 告警 + 记录 | 看见了也拦不住 |
| IPS | 串联 | 七层 | 实时阻断 | 误报断业务、自身单点故障 |

**选型口诀**：能阻断的都要先问「挂了怎么办」——**Bypass、HA、误报调优、性能评估，四件套缺一不可**。

**绕过防火墙三件套**：合法端口 + 加密流量 + 应用层载荷。
